Sign

Sign and verify component versions so consumers can trust their authenticity and integrity.

Signing certifies that a component version is authentic and has not been tampered with. These guides walk you through generating keys, configuring signing credentials, and both sides of each method: a sign guide for producers and a matching verify guide for consumers (plain RSA, PEM certificate chains, GPG, and keyless Sigstore).

Verify a signature

To validate a component version signature, pick the method that matches the algorithm the signature was made with. Each page is a self-contained walkthrough.

MethodWhen to use itSignVerify
Plain RSAAn RSA key pair; the consumer verifies with the signer’s public key on disk.Sign with Plain RSAVerify Plain RSA
PEM certificate chainAn X.509 chain embedded in the signature; the consumer pins the signer’s root CA.Sign with a PEM Certificate ChainVerify a PEM Certificate Chain
GPGA GPG (OpenPGP) key; the consumer verifies with the signer’s public key or keyring.Sign with GPGVerify GPG
Sigstore (keyless)No key pair; the consumer declares which OIDC identity to trust, interactively or in CI.Sign with Sigstore (Keyless)Verify Sigstore (Keyless)

Not sure which algorithm was used? List the signatures on the component and read the algorithm field:

  • RSASSA-PSS (default) or RSASSA-PKCS1-V1_5, mediaType application/vnd.ocm.signature.rsa.pss → Verify Plain RSA
  • a PEM-encoded signature, mediaType application/x-pem-file → Verify a PEM Certificate Chain
  • an OpenPGP signature → Verify GPG
  • Sigstore/v1alpha1 → Verify Sigstore (Keyless)
